## How it works

- **Tests are scheduled events.** "Live" is derived from `starts_at`/`ends_at` — no cron needed.
- **Answers never reach the browser before submit.** `mock_test_questions` has no client
  privileges at all; questions are served answer-free via `get_mock_questions()`,
  and grading happens in `submit_mock_attempt()` (SECURITY DEFINER).
- **One ranked attempt per user** per test (`unique (mock_test_id, user_id)`).
- **Leaderboard** reads submitted attempts only, via column-level grants (the `answers`
  column is never granted to clients). Live updates use Supabase Realtime on
  `mock_attempts`; rank ties break by faster `time_taken_seconds`.
- **`is_free = true`** → any signed-in user can take it (the lead-magnet strategy).
  `false` → requires an active `subscriptions` row (checked in `start_mock_attempt`).

## Setup (one time)

1. Supabase dashboard → SQL editor → paste
   `supabase/migrations/20261013_mock_tests.sql` → Run.
   (Idempotent — safe to re-run.)
2. Realtime is enabled by the migration itself (`alter publication … add table`).
   Verify: Dashboard → Database → Replication → `supabase_realtime` includes `mock_attempts`.
3. Deploy the branch (Vercel preview or merge to `main`). The page is served at
   `/mock-test` via the existing `/(.*) → /index.html`… actually via `cleanUrls`:
   `mock-test.html` is served at `/mock-test` automatically.

## Creating your first mock test

Use the commented seed template at the bottom of the migration file: it creates a
"NEET PG Grand Test #1" event and snapshots 200 random questions from the
`questions` bank into it. Adjust dates, then set `status = 'published'`.

Or insert manually:

```sql
insert into public.mock_tests
  (title, exam, description, starts_at, ends_at, duration_minutes,
   total_questions, positive_marks, negative_marks, status, is_free)
values
  ('INI-CET Grand Test #1 — Free All-India Mock', 'INI-CET',
   '200 questions · 3 hours · +4/-1 · live All-India rank.',
   '2026-10-26 10:00:00+05:30', '2026-10-26 13:00:00+05:30',
   180, 200, 4, 1, 'published', true);
```

Then snapshot questions (see template). Curate rather than pure-random for a real
event: balance subjects the way the actual exam blueprint does.

## Notes / limits

- Auth is Supabase Auth (same as the main app: Google, email/password, magic link).
- Display names come from the user's auth metadata (fallback: email prefix).
- Late submits are accepted and graded; `time_taken_seconds` reflects reality.
- Refreshing mid-test resumes from the server deadline; answers are also backed
  up to `localStorage` per attempt.
- The page does not yet appear in the main app's navigation — add a "Mock Tests"
  entry point in `app.js` `renderHome()` (or the top bar) before the public launch.
- `sitemap.xml` is generated by `generate_seo.py`; add `/mock-test` to the
  generator's static URL list so it gets indexed.
